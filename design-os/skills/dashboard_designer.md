# Dashboard Designer Skill

**Version:** 1.0
**Status:** Expert Data Product Design Skill
**Priority:** Dashboard Experience Authority

---

# Purpose

The Dashboard Designer Skill defines the expertise responsible for designing dashboards that transform complex information into clear, actionable experiences.

A dashboard is not a place where data is displayed.

A dashboard is a decision-making environment.

It helps users:

* monitor important signals
* understand performance
* identify problems
* take action

---

# Core Role

The Dashboard Designer converts business requirements and data into structured, usable interfaces.

Primary responsibility:

```text id="a8k4mv"
Understand User Decisions

↓

Define Information Hierarchy

↓

Design Dashboard Structure

↓

Select Data Components

↓

Optimize User Workflow
```

---

# Dashboard Designer Responsibilities

The Dashboard Designer evaluates:

## User Goals

Understand:

* who uses the dashboard
* what decisions they make
* what information they need
* how frequently they return

---

## Data Meaning

Determine:

* important metrics
* relationships between values
* trends
* anomalies
* required actions

---

## Interface Structure

Define:

* layout
* information priority
* component placement
* interaction patterns

---

# Dashboard Design Framework

Before designing:

Ask:

```text id="h7m3qx"
Who is the audience?

What decisions must they make?

Which metrics matter most?

What action follows each insight?

What information can be removed?
```

# Dashboard Types

Identify the dashboard category:

## Executive Dashboard

Focus:

* business health
* strategic indicators
* trends

Characteristics:

* low density
* high-level insights

---

## Operational Dashboard

Focus:

* daily activity
* current status
* workflow management

Characteristics:

* actionable
* frequently updated

---

## Analytics Dashboard

Focus:

* exploration
* comparison
* discovery

Characteristics:

* flexible
* data-rich

---

## Admin Dashboard

Focus:

* management
* configuration
* system control

Characteristics:

* functional
* task-oriented

# Metric Design

A metric should communicate:

```text id="q8m2pz"
Value

↓

Meaning

↓

Change

↓

Context

↓

Action
```

Example:

```text id="r3v7mk"
Orders

1,240

+18%

Compared to last month
```

---

# Card Design Rules

Cards should:

* group related information
* support scanning
* maintain consistent structure

Avoid:

* excessive card usage
* hiding relationships between metrics

---

* trends over time

---

## Bar Chart

Use for:

* comparisons

---

## Area Chart

Use for:

* volume changes

## Table

Use for:

* exact values

* actions

* preserve context


# Empty Dashboard Design

An empty dashboard should:

Explain:

* why no information exists
* how to create activity
* what the user can do

---

# Responsive Dashboard Design

Desktop:

* multiple columns
* detailed analysis

Tablet:

* reduced layout

Mobile:

* prioritized information
* stacked components
* simplified interactions

Avoid:

* shrinking desktop dashboards

---

# Accessibility Requirements

Dashboards must support:

* keyboard navigation
* screen readers
* readable charts
* accessible tables

Never rely only on:

* color
* position
* visual indicators

---

# Dashboard Performance

Optimize:

* data loading
* chart rendering
* filtering speed
* large datasets

Use:

* pagination
* aggregation
* caching

---

# Dashboard Anti-Patterns

Reject:

* metric overload
* meaningless charts
* no user action
* equal importance everywhere
* poor hierarchy
* decorative analytics

---

# Dashboard Review Checklist

Before approval:

```text id="n6q4mz"
Does it support decisions?

Are important insights obvious?

Are actions connected to information?

Is complexity controlled?

Does it work responsively?

Are states complete?

Is it accessible?
```

---

# Final Rule

A dashboard designer does not organize data.

A dashboard designer organizes decisions.

The best dashboards make important information impossible to miss and unnecessary information easy to ignore.
