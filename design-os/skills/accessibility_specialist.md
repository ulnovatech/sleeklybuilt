# Accessibility Specialist Skill

**Version:** 1.0
**Status:** Expert Inclusive Design Skill
**Priority:** Accessibility Quality Authority

---

# Purpose

The Accessibility Specialist Skill defines the expertise responsible for ensuring digital products are usable by people with diverse abilities, devices, and interaction needs.

Accessibility is not an optional enhancement.

It is a fundamental quality requirement.

A high-quality product should work for:

* different abilities
* different environments
* different devices
* different input methods

---

# Core Role

The Accessibility Specialist ensures accessibility is considered throughout the entire design and development process.

Primary responsibility:

```text id="m7q4vx"
Understand Accessibility Needs

↓

Evaluate Product Experience

↓

Identify Barriers

↓

Recommend Improvements

↓

Validate Inclusive Quality
```

---

# Accessibility Principles

The specialist applies the four core accessibility principles:

```text id="c8n5qp"
Perceivable

Operable

Understandable

Robust
```

---

# Perceivable Design

Information must be available through multiple senses.

Consider:

* visual alternatives
* audio alternatives
* readable content
* clear structure

---

# Visual Accessibility

Evaluate:

## Color

Ensure:

* sufficient contrast
* meaningful color usage
* non-color alternatives

Avoid:

* communicating only through color

Example:

Weak:

```text id="h4x7mv"
Red = Error
```

Better:

```text id="p8k2qa"
Error icon + message + color
```

---

## Typography

Ensure:

* readable sizing
* scalable text
* comfortable spacing
* clear hierarchy

Avoid:

* tiny text
* low contrast text

---

# Operable Interfaces

Users should be able to interact through different methods.

Support:

* keyboard navigation
* touch interaction
* assistive technologies
* alternative inputs

---

# Keyboard Accessibility

Requirements:

* visible focus states
* logical tab order
* accessible controls

Avoid:

* keyboard traps
* inaccessible custom components

---

# Touch Accessibility

Ensure:

* adequate target sizes
* sufficient spacing
* predictable interactions

Avoid:

* tiny controls
* precision-only interactions

---

# Understandable Experiences

Interfaces should communicate clearly.

Support:

* consistent patterns
* understandable language
* predictable behavior

Avoid:

* confusing terminology
* unexpected interactions

---

# Robust Implementation

Products should work across:

* browsers
* devices
* assistive technologies

Consider:

* semantic HTML
* proper component structure
* accessibility APIs

---

# Screen Reader Considerations

Support:

* meaningful labels
* logical reading order
* descriptive controls

Avoid:

* unlabeled buttons
* meaningless announcements

---

# Form Accessibility

Forms should include:

* clear labels
* helpful errors
* input descriptions
* validation feedback

Avoid:

* placeholder-only labels
* unclear requirements

---

# Navigation Accessibility

Ensure users can:

* understand location
* move between sections
* identify current page

Provide:

* landmarks
* headings
* navigation structure

---

# Media Accessibility

Support:

## Images

Use:

* meaningful alternative text

---

## Video

Provide:

* captions
* transcripts where needed

---

## Audio

Provide:

* text alternatives

---

# Motion Accessibility

Consider:

* reduced motion preferences
* flashing content risks
* animation intensity

Avoid:

* motion that causes discomfort
* essential information communicated only through movement

---

# Accessibility Testing

Evaluate through:

## Automated Checks

Check:

* contrast
* structure
* labels
* common violations

---

## Manual Testing

Review:

* keyboard usage
* screen reader experience
* real interaction flows

---

# Accessibility Review Process

Evaluate:

```text id="x9m4pq"
Can everyone perceive the content?

Can everyone operate the interface?

Can everyone understand the experience?

Does it work with assistive technology?
```

---

# Accessibility Anti-Patterns

Reject:

* accessibility added at the end
* color-only communication
* missing labels
* inaccessible custom controls
* keyboard barriers
* ignoring text scaling

---

# Review Checklist

Before approval:

```text id="v5k8mw"
Are contrast requirements met?

Can keyboard users navigate?

Are controls labeled?

Are forms understandable?

Does screen reader navigation work?

Are motion preferences respected?

Is accessibility built into components?
```

---

# Final Rule

Accessibility is quality.

A product that excludes users is an incomplete product.

The Accessibility Specialist ensures every person has a meaningful path through the experience.
