# iOS HIG Specialist Skill

**Version:** 1.0
**Status:** Expert Platform Design Skill
**Priority:** Apple Human Interface Guidelines Authority

---

# Purpose

The iOS HIG Specialist Skill defines the expertise responsible for creating iOS experiences that feel native, intuitive, accessible, and aligned with Apple's Human Interface Guidelines.

The goal is not to copy Apple interfaces.

The goal is to understand the principles behind them:

* clarity
* deference
* depth
* familiarity
* direct manipulation

---

# Core Role

The iOS HIG Specialist ensures mobile products respect iOS interaction patterns while maintaining product identity.

Primary responsibility:

```text id="q2l8sa"
Understand iOS Principles

↓

Evaluate User Interaction

↓

Apply Native Patterns

↓

Optimize Experience

↓

Validate Platform Quality
```

---

# iOS Design Philosophy

iOS experiences should prioritize:

## Clarity

Users should understand:

* what is available
* what happened
* what action is possible

---

## Deference

The interface should support content.

Avoid:

* unnecessary visual competition
* excessive decoration

---

## Depth

Use:

* layering
* hierarchy
* motion
* transitions

to communicate relationships.

# Navigation Systems

Choose appropriate patterns:

## Navigation Stack

Used for:

* hierarchical content
* detail views

Example:

```text id="u1x6mk"
List

↓

Detail

↓

Sub Detail
```

---

## Tab Bar Navigation

Used for:

* primary destinations
* frequent switching

Rules:

* limit major sections
* maintain clear labels

---

## Sheets

Used for:

* temporary tasks
* focused workflows

Examples:

* forms
* selections
* secondary actions

---

# iOS Controls

Use familiar patterns for:

## Buttons

Should communicate:

* importance
* action
* state

---

## Toggles

Use for:

* immediate settings
* binary choices

---

## Pickers

Use for:

* selecting options
* reducing input effort

---

# Touch And Gesture Design

Support:

* tap
* swipe
* drag
* long press

Gestures should:

* be discoverable
* have alternatives
* provide feedback

Avoid:

* hidden critical actions behind gestures

---

# Typography System

Follow iOS readability principles:

Prioritize:

* Dynamic Type
* readable sizes
* strong hierarchy

Avoid:

* fixed text sizes that break accessibility

---

# Color System

Color should communicate:

* hierarchy
* interaction
* status

Avoid:

* relying only on color for meaning

---

# Materials And Visual Layers

Use depth appropriately:

Examples:

* translucent surfaces
* grouped content areas
* elevated controls

Avoid:

* excessive effects that reduce clarity

---

# Motion Guidelines

Motion should explain:

* where content came from
* where it goes
* what changed

Good motion:

* reinforces navigation
* confirms actions
* maintains continuity

Avoid:

* unnecessary animation

---

# iOS Forms

Forms should:

* group related information
* minimize effort
* use appropriate controls

Prefer:

* autofill
* native keyboards
* smart defaults

---

# Error Handling

Errors should:

* explain the issue
* suggest recovery
* avoid blame

Good:

```text id="g2x7rp"
Unable to save changes.

Check your connection and try again.
```

---

# Accessibility Requirements

iOS experiences must support:

* VoiceOver
* Dynamic Type
* Reduce Motion
* sufficient contrast
* accessible touch targets

---

# Responsive Considerations

Support:

* iPhone sizes
* iPad layouts
* landscape orientation

Adapt:

* navigation
* content density
* interactions

---

# iOS Performance

Optimize:

* animations
* scrolling
* images
* memory usage

Prioritize:

* responsiveness
* battery efficiency

---

# iOS HIG Anti-Patterns

Reject:

* non-native interaction patterns
* tiny touch targets
* confusing navigation
* unnecessary gestures
* poor Dynamic Type support
* ignoring platform conventions

---

Before approval:

```text id="n8q4wp"
Does it feel native?

Is navigation predictable?

Are controls familiar?

Does typography scale?

Are gestures discoverable?

```

# Final Rule

The iOS HIG Specialist creates experiences that feel natural because they respect how iOS users already think and interact.

A great iOS app does not imitate Apple.

It understands Apple's principles and applies them with purpose.
