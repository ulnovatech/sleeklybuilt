# SaaS Product Design Prompt

**Version:** 1.0
**Status:** Production SaaS Experience Design Prompt
**Priority:** Software Product Experience Authority

---

# Purpose

This prompt defines the process for designing production-quality SaaS products using the Design OS framework.

A SaaS product is not a collection of screens and features.

It is an ongoing system that helps users:

* accomplish recurring tasks
* manage workflows
* make decisions
* collaborate
* achieve measurable outcomes

---

# Design Mission

When creating a SaaS product:

```text id="n7x4qa"
Understand User Workflow

↓

Define Product Value

↓

Design Information Architecture

↓

Create Core Experiences

↓

Validate User Success

↓

Prepare For Scale
```

---

# Before Designing

Analyze:

## User Context

Determine:

* user roles
* responsibilities
* goals
* frequency of use
* skill level

---

## Business Context

Understand:

* product purpose
* pricing model
* customer lifecycle
* retention drivers
* success metrics

---

# SaaS Principles

## Users Return For Outcomes

A SaaS product must help users repeatedly achieve value.

Ask:

```text id="m8q2vx"
What job does this product help complete?

How often does the user need it?

What makes them return?
```

---

Settings And Management

---

# Onboarding Design

Onboarding should:

* explain value quickly
* guide setup
* create early success

Avoid:

* long tutorials
* unnecessary questions
* forcing users to configure everything first

---

# Workspace Design

The workspace is the user's operating environment.

Design around:

* primary tasks
* important information
* frequent actions

Avoid:

* empty dashboards
* feature overload

---

# Navigation Design

SaaS products often contain complex functionality.

Navigation should support:

* discovery
* efficiency
* organization

Use:

* clear categories
* predictable placement
* role-based visibility

---

# Feature Design

Every feature should answer:

```text id="v3m9qa"
Who needs this?

What problem does it solve?

How often is it used?

What happens after completion?
```

---

# Data And Information Design

SaaS interfaces often manage complex information.

Prioritize:

* clarity
* hierarchy
* searchability
* filtering
* organization

Avoid:

* displaying everything at once

---

# Collaboration Features

For team products, consider:

* permissions
* ownership
* comments
* activity history
* notifications

Collaboration should increase productivity, not noise.

---

# Forms And Workflows

Complex workflows should use:

* progressive disclosure
* smart defaults
* validation
* saved progress

Avoid:

* overwhelming forms
* unnecessary configuration

---

# Empty States

Empty states should help users start.

Include:

```text id="c6q8mp"
Explanation

↓

Example

↓

Next Action
```

Avoid:

* blank screens
* unexplained absence of data

---

# Error Handling

Errors should:

* explain what happened
* protect user work
* provide recovery options

Avoid:

* technical error messages
* lost progress

---

# SaaS States

Every feature should support:

```text id="k4m7vx"
Loading

↓

Empty

↓

Active

↓

Error

↓

Completed
```

---

# Responsive SaaS Design

Consider:

## Desktop

Optimize for:

* productivity
* complex workflows
* multiple information areas

---

## Tablet

Adapt:

* navigation
* density
* interactions

---

## Mobile

Prioritize:

* essential actions
* notifications
* quick updates

Avoid:

* forcing desktop workflows onto mobile

---

# Accessibility Requirements

SaaS products must support:

* keyboard workflows
* readable interfaces
* accessible data displays
* screen readers
* clear focus states

---

# Performance Requirements

Optimize:

* large datasets
* dashboards
* search
* real-time updates
* complex interactions

---

# SaaS Quality Checklist

```text id="z9m5qa"
✓ User workflow is clear

✓ Product value is obvious

✓ Navigation scales

✓ Core tasks are efficient

✓ States are complete

✓ Collaboration is understandable

✓ Accessibility is supported

✓ Performance is reliable

```

---

# Final Instruction

Create SaaS products that become essential tools in users' workflows.

Do not design feature collections.

Design systems that help people consistently achieve valuable outcomes.
