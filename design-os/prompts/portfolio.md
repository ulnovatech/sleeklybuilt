# Portfolio Design Prompt
**Version:** 1.0  
**Status:** Production Portfolio Experience Design Prompt  
**Depends On:** Product Classifier, Landing Page Intelligence, Content Intelligence, Visual Language, Accessibility Intelligence

---

# Purpose

This prompt defines the process for designing production-quality portfolio experiences using the Design OS framework.

A portfolio is not a gallery of completed work.

A strong portfolio is a proof system designed to:

- demonstrate capability
- explain thinking
- establish credibility
- help visitors evaluate expertise

---

# Design Mission

```
Understand Audience

↓

Define Desired Perception

↓

Organize Work Strategically

↓

Present Case Studies

↓

Build Trust Honestly

↓

Guide Next Action
```

---

# Before Designing

## Audience

Who is viewing, what they must evaluate, and what influences their decision (clients, employers, collaborators, investors).

## Portfolio Goal

Primary outcome: inquiry, employment, partnership, or credibility.

Avoid portfolios without a defined outcome.

---

# Portfolio Principles

## Show Thinking, Not Just Results

```
Problem

↓

Approach

↓

Execution

↓

Outcome
```

Avoid unexplained screenshots and visual-only galleries.

## Honesty Over Theater

No invented metrics, fake testimonials, or borrowed logos. Consult Content Intelligence honesty rules.

---

# Portfolio Architecture

```
Introduction

↓

Featured Work

↓

Case Studies

↓

Capabilities

↓

Process

↓

About

↓

Contact
```

Featured work is curated. Not every project deserves equal weight.

---

# Hero Section

Communicate who you are, what you create, and why the work matters.

Visitors must answer quickly:

```
Who is this?
What do they do?
Why should I continue?
```

Brand-first rule: the name or identity must be a hero-level signal, not only nav text.

---

# Project And Case Study Quality

Each project includes context, strategy, execution, and outcome.

A case study must answer:

```
What was the problem?
Why was this solution chosen?
How was it built?
What changed?
```

Outcomes must be verifiable or clearly qualitative. Do not invent percentages.

---

# Visual Presentation

High-quality imagery, realistic product views, clear layouts, focused storytelling.

Avoid cluttered mockups and decoration that competes with the work.

---

# Navigation And Interaction

Help users explore featured work, categories, services, and background.

Interactive demos are welcome when they demonstrate ability. Reject effects without purpose.

---

# Trust Building

Use real testimonials, measurable outcomes you can defend, process transparency, and client feedback with permission.

Avoid unsupported claims.

---

# Responsive, Performance, Accessibility

Must work on mobile, tablet, and desktop.

Prioritize project browsing, image quality, readability, and contact access.

Optimize images, video, and animation. Provide image alternatives, keyboard access, semantic structure, and contrast.

---

# Decision Criteria

Approve when:

- Audience and outcome are explicit
- Featured work selection is intentional
- Case studies explain decisions, not only visuals
- Primary CTA to contact or inquire is clear
- Proof is honest
- Mobile browsing of work is first-class

---

# Anti-Patterns

Reject:

- screenshot dumps without narrative
- every project weighted equally
- fake metrics or vague “increased engagement”
- contact forms with no human path
- autoplaying heavy media that blocks browsing
- portfolios that look like template galleries for any creator

---

# Portfolio Output

Example:

```
Audience

Series A startups hiring product design leads

Goal

Book intro call

Featured

3 case studies max on home; archive for the rest

Case Study Skeleton

Problem → Constraints → Decisions → System → Outcome

Proof

Named client quotes with permission; no invented NPS

CTA

Book a call

Mobile

Case study images lazy-loaded; TOC jump links

Review

Pass
```

---

# Failure Conditions

Fails when:

- Work cannot be evaluated because thinking is absent
- Claims cannot be verified
- Contact path is unclear
- Mobile experience makes case studies unreadable

---

# Quality Checklist

```
✓ Purpose is clear
✓ Work is strategically presented
✓ Case studies explain decisions
✓ Visual quality is high
✓ Navigation is simple
✓ Trust is established honestly
✓ Mobile experience works
✓ Performance is optimized
✓ Accessibility is supported
```

---

# Review Questions

- Can a visitor understand expertise in under a minute?
- Does each featured project teach a decision, not only a look?
- Is the next action obvious?
- Would removing any project strengthen the portfolio?

---

# Final Instruction

Create portfolios that communicate expertise through evidence.

Do not build collections of screenshots. Build experiences that help people understand the value, thinking, and quality behind the work.
