# Dashboard Design Prompt

**Version:** 1.0
**Status:** Production Dashboard Design Generation Prompt
**Priority:** Data Experience Creation Authority

---

# Purpose

This prompt defines the process for designing production-quality dashboards using the Design OS framework.

A dashboard is not a collection of widgets.

A dashboard is a decision-making environment that helps users:

* understand information
* identify important changes
* monitor performance
* take action efficiently

---

# Design Mission

When creating a dashboard:

```text id="a7m4qp"
Understand User Role

↓

Identify Decisions

↓

Define Information Needs

↓

Structure Data Hierarchy

↓

Design Dashboard Experience

↓

Validate Usability
```

---

# Before Designing

Analyze:

## User Context

Determine:

* who uses the dashboard
* their responsibilities
* their frequency of use
* their required decisions

---

## Business Context

Understand:

* key metrics
* operational goals
* important workflows
* success indicators

---

# Dashboard Principles

## Information Before Decoration

Every element must answer:

```text id="n5q8vx"
What does the user need to know?

Why does it matter?

What action follows?
```

Avoid:

* decorative charts
* unnecessary metrics
* information overload

---

# Dashboard Architecture

Define:

## Overview Layer

Provides:

* current status
* important summaries
* key changes

---

## Analysis Layer

Provides:

* trends
* comparisons
* deeper information

---

## Action Layer

Provides:

* tasks
* alerts
* next steps

---

# Layout Strategy

A dashboard should establish hierarchy:

```text id="c8m3qa"
Most Important Information

↓

Supporting Metrics

↓

Detailed Data

↓

Secondary Actions
```

---

# Information Density

Match complexity to user needs.

Consider:

* user expertise
* frequency of usage
* decision importance

Avoid:

* overwhelming users
* hiding important information

---

# Metric Design

Every metric should communicate:

```text id="v6p9mw"
Value

↓

Meaning

↓

Change

↓

Action
```

Include when useful:

* current value
* previous comparison
* trend direction
* status

---

# Data Visualization Rules

Choose visualization based on purpose.

Use:

## Numbers

For:

* exact values
* simple status

---

## Charts

For:

* trends
* comparisons
* relationships

---

## Tables

For:

* detailed records
* scanning information

---

# Chart Design Requirements

Charts must:

* have clear labels
* avoid unnecessary complexity
* highlight important information
* support interpretation

Avoid:

* meaningless visualizations
* excessive colors
* unclear axes

---

# Dashboard Components

Use consistent patterns:

* metric cards
* charts
* tables
* filters
* activity feeds
* alerts
* navigation

Every component requires:

* loading state
* empty state
* error state
* responsive behavior

---

# Filtering And Search

Design filters that:

* are easy to understand
* preserve context
* provide feedback

Avoid:

* hidden filtering logic
* confusing controls

---

# Responsive Dashboard Design

Desktop:

* multiple information areas
* expanded data views

Tablet:

* reorganized layouts
* adjusted density

Mobile:

* prioritized information
* simplified interactions

Avoid:

* shrinking desktop dashboards onto mobile

---

# Dashboard Interaction Design

Support:

* drill-down
* sorting
* filtering
* comparison
* actions

Every interaction should provide:

* feedback
* confirmation
* clear results

---

# Accessibility Requirements

Dashboards must support:

* readable charts
* accessible tables
* keyboard navigation
* screen readers
* sufficient contrast

Do not rely only on visual indicators.

---

# Performance Requirements

Optimize:

* large datasets
* chart rendering
* filtering speed
* loading states

Use:

* pagination
* virtualization
* progressive loading

when appropriate.

---

# Dashboard Quality Checklist

```text id="k2p7vx"
✓ User goals are understood

✓ Important information is prioritized

✓ Metrics are meaningful

✓ Charts communicate clearly

✓ Actions are obvious

✓ States are complete

✓ Mobile behavior works

✓ Accessibility is supported

✓ Performance is acceptable
```

---

# Final Instruction

Create dashboards that help users think, decide, and act.

Do not build screens full of data.

Build interfaces that transform data into understanding.
