# Design Principles
**Version:** 1.0  
**Status:** Canonical  
**Depends On:** Design Constitution

---

# Purpose

This document defines **how** Design OS applies the Constitution when designing interfaces.

The Constitution defines **what** we believe.

This document defines **how** we make decisions.

Every intelligence module, component, skill, and review process must follow these principles.

---

# Principle 1 — Design for the User's Goal

Every screen exists to help the user accomplish a specific goal.

Never design around components.

Never design around aesthetics.

Never design around available space.

Instead ask:

- What is the user's goal?
- What is preventing them from reaching it?
- What is the fastest path to success?

---

# Principle 2 — Reduce Cognitive Load

Every design decision should reduce thinking.

The interface should answer questions before users ask them.

Users should never wonder:

- What does this do?
- Where do I click?
- What happens next?
- Did this work?

Good interfaces remove uncertainty.

---

# Principle 3 — Information Has Weight

Not all information deserves equal attention.

Every screen must establish hierarchy.

Priority order:

1. Primary Action
2. Primary Content
3. Supporting Content
4. Secondary Actions
5. Metadata
6. Decorative Elements

Visual weight must follow information importance.

---

# Principle 4 — Layout Before Components

Never start with components.

Start with layout.

Determine:

- Reading flow
- Interaction flow
- Content grouping
- Navigation
- Screen rhythm

Only then choose components.

---

# Principle 5 — Components Solve Problems

Components are tools.

Never use a component simply because it exists.

Ask:

Why is this component here?

If it cannot answer a user problem,

remove it.

---

# Principle 6 — Design Around Content

Content defines layout.

Layout never defines content.

Interfaces must gracefully support:

- long titles
- short titles
- empty values
- missing images
- large datasets
- localization
- accessibility settings

---

# Principle 7 — Mobile Determines Everything

Every feature must work beautifully on mobile before desktop.

Never shrink desktop layouts.

Instead redesign for mobile.

Desktop expands.

Mobile defines.

---

# Principle 8 — One Primary Action

Every screen should have one obvious primary action.

Users should never wonder:

"What should I do now?"

Primary actions should dominate.

Secondary actions should support.

---

# Principle 9 — Minimize Interaction Cost

Prefer:

1 tap

over

2 taps

Prefer:

one screen

over

two screens.

Every interaction carries cost.

Reduce it whenever possible.

---

# Principle 10 — Consistency Creates Trust

Users should never relearn the interface.

Navigation

Typography

Spacing

Buttons

Forms

Colors

Feedback

Motion

must remain consistent.

---

# Principle 11 — Every Pixel Must Earn Its Place

Before placing anything ask:

Does this improve:

- understanding
- navigation
- completion
- confidence

If not,

remove it.

---

# Principle 12 — Progressive Disclosure

Complexity should appear only when needed.

Show:

only what users need now.

Hide:

everything else until relevant.

---

# Principle 13 — White Space Is Functional

Whitespace is not empty.

Whitespace creates:

- hierarchy
- readability
- rhythm
- focus

Never fill space simply because it exists.

---

# Principle 14 — Typography Is the Interface

Typography carries more responsibility than color.

Typography should communicate:

- hierarchy
- confidence
- rhythm
- clarity
- personality

Good typography eliminates confusion.

---

# Principle 15 — Motion Has Meaning

Every animation must answer:

What changed?

Why?

Where did it go?

Where did it come from?

Never animate for decoration.

---

# Principle 16 — Errors Should Build Confidence

Users should never feel blamed.

Errors should explain:

- what happened
- why
- how to recover

Recovery should always be easier than failure.

---

# Principle 17 — Empty States Should Teach

Empty screens are onboarding opportunities.

Every empty state should explain:

- why nothing is here
- what users can do
- how to get started

Never waste an empty state.

---

# Principle 18 — Performance Is UX

Users perceive speed before beauty.

Avoid:

- unnecessary rendering
- unnecessary requests
- unnecessary animations
- unnecessary scrolling

Fast products feel intelligent.

---

# Principle 19 — Accessibility Is Design

Accessibility is not a checklist.

Accessibility is part of good design.

Design for:

- keyboard navigation
- screen readers
- color blindness
- reduced motion
- large text
- touch ergonomics

Good accessibility benefits everyone.

---

# Principle 20 — Design for Real Life

Users:

lose connection.

make mistakes.

get interrupted.

switch devices.

use one hand.

use sunlight.

use old phones.

Design for reality.

Never ideal conditions.

---

# Principle 21 — Delight Is the Result, Not the Goal

Do not chase delight.

Chase clarity.

Delight naturally follows:

- confidence
- simplicity
- speed
- polish
- consistency

---

# Principle 22 — Premium Means Invisible

Premium design does not draw attention to itself.

It feels obvious.

Natural.

Expected.

Users should notice:

their progress.

Not the interface.

---

# Principle 23 — Remove Before Adding

Whenever solving a problem ask:

Can this screen disappear?

Can this component disappear?

Can this click disappear?

Can this field disappear?

Removing is usually the best design decision.

---

# Principle 24 — The Design System Always Wins

Individual creativity must never damage consistency.

If a design conflicts with the system,

improve the system,

not the screen.

---

# Principle 25 — Every Screen Must Be Reviewable

Every screen should pass independent review for:

- usability
- accessibility
- consistency
- performance
- responsiveness
- visual polish

If review fails,

the design is incomplete.

---

# Final Principle

Design should feel inevitable.

Users should never think:

"This interface is beautiful."

They should think:

"This was incredibly easy to use."

That is the highest compliment a product can receive.
