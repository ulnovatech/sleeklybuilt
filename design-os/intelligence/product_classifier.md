# Product Classifier
**Version:** 1.0  
**Status:** Intelligence Layer  
**Depends On:** Design Constitution, Design Principles, Quality Bar, Visual Language

---

# Purpose

Before designing **anything**, Design OS must first determine **what kind of product it is designing**.

No layout...

No typography...

No colors...

No navigation...

No components...

...may be selected until the product has been classified.

The Product Classifier is the first intelligence executed for every project.

Every other intelligence module depends on its output.

---

# Design Pipeline

Every new project follows this order:

```
Understand

↓

Classify

↓

Strategize

↓

Design

↓

Review

↓

Build
```

Never skip classification.

# Failure Conditions

Classification fails if:

- Product type is unknown.
- User is undefined.
- Primary action is unclear.
- Personality conflicts.
- Navigation is selected before classification.
- Typography is chosen before personality.
- Components are selected before layout.
- Colors are selected before emotional context.

If any failure occurs,

repeat classification.

---

# Final Rule

Never ask:

> "What components should I use?"

Always ask:

> "What kind of product am I designing, who is it for, and what is the fastest, clearest, and most trustworthy way to help them succeed?"

Everything else in Design OS begins with that answer.

# Purpose

The Product Classifier determines the design direction before implementation begins.

It answers:

- What type of product is this?
- Who uses it?
- What experience expectations exist?
- Which design patterns should be prioritized?
- Which patterns should be avoided?

The goal is to prevent generic interfaces.

---

# Core Philosophy

A restaurant app, banking app, SaaS dashboard, marketplace, and portfolio site should not look or behave the same.

Design begins with understanding the product category.

- accessibility

- clarity

## Ecommerce

Prioritize:

- discovery

Prioritize:

- productivity
- hierarchy
- workflows

- marketing-style layouts inside the app

---

Prioritize:

- progress feedback
- conversational UX

- pretending AI is magic

---

## Portfolio / Marketing

- storytelling
- typography

# Failure Conditions

Product classification fails when:

- every project receives the same style
- components are selected before understanding users
- visual trends override product purpose
- mobile behavior is ignored
- design personality is accidental

---

# Final Rule

The first design decision is not color.

It is understanding what kind of product is being built.

A great interface begins with the right identity.
