# Layout Intelligence
**Version:** 1.0  
**Status:** Intelligence Layer  
**Depends On:** Product Classifier, Mobile First, Typography Intelligence, Color Intelligence

---

# Purpose

Layout Intelligence determines how information, components, and interactions are arranged on the screen.

Layout is not decoration.

Layout is the structure that determines:

- what users notice
- what they understand
- what they do next
- how quickly they complete tasks

A beautiful component in a poor layout is still a poor interface.

---

# Core Philosophy

Never begin with components.

Begin with:

- user goal
- information hierarchy
- interaction flow
- content priority

Components are placed inside a strategy.

---

```
Product Classification

↓

Responsive Adaptation
```

---

# Step 1 — Understand the User Task

Determine:

What is the user trying to accomplish?

Examples:

Browse products

Complete purchase

Analyze data

Create content

Manage settings

Track progress

Communicate

The layout must optimize the task.

---

# Step 2 — Identify Information Priority

Classify information.

## Primary

Must be immediately visible.

Examples:

- Main action
- Current status
- Main content

---

## Secondary

Useful but not dominant.

Examples:

- Filters
- Supporting information
- Related actions

---

## Tertiary

Optional.

Examples:

- Metadata
- Advanced settings
- Additional context

---

# Step 3 — Choose Layout Pattern

Never default to one pattern.

Choose based on product requirements.

# Mobile Layout Rules

Mobile layouts must prioritize:

1. Primary action
2. Essential information
3. Navigation
4. Secondary options

Avoid:

- excessive columns
- compressed desktop layouts
- tiny controls
- complex grids

---

# Desktop Layout Rules

Desktop should expand the mobile experience.

Use additional space for:

- supporting panels
- additional context
- productivity improvements

Do not create unrelated desktop workflows.

---

# Grid System

All layouts should use a consistent grid.

Preferred:

Mobile:

4-column thinking

Tablet:

8-column thinking

Desktop:

12-column thinking

The exact implementation may vary.

Consistency matters more than numbers.

---

# Spacing Strategy

Spacing creates hierarchy.

Use spacing to communicate:

Related items:

closer together

Unrelated items:

further apart

Never rely only on borders.

---

# Container Strategy

Avoid uncontrolled full-width layouts.

Use:

- content containers
- readable widths
- intentional margins

---

# Visual Rhythm

Every page should have rhythm.

A good rhythm includes:

Large sections

↓

Medium groups

↓

Small details

Avoid:

same spacing everywhere

---

# Cards Strategy

Cards are not a default layout.

Use cards when they:

- group related content
- create separation
- improve scanning

Avoid:

one card per item

card stacks everywhere

card-based websites

---

# Lists Strategy

Prefer lists when users need:

- comparison
- scanning
- repeated information

Examples:

Orders

Messages

Settings

Search results

---

# Forms Layout

Forms should follow user thinking.

Group related fields.

Avoid:

long uncontrolled forms

unnecessary sections

confusing ordering

---

# Navigation Layout

Navigation must match user frequency.

High frequency:

Persistent navigation

Low frequency:

Secondary navigation

Advanced:

Hidden until needed

---

# Empty Space

Empty space is intentional.

Use it to:

- highlight important content
- reduce cognitive load
- create premium feeling

Never fill empty space without purpose.

---

# Responsive Transformation

Responsive design is not:

desktop → smaller desktop

It is:

desktop → adapted experience

Examples:

Desktop sidebar

becomes

Mobile bottom navigation

---

Desktop table

becomes

Mobile cards/list

---

Desktop multi-column

becomes

Mobile hierarchy

---

# Layout Anti-Patterns

Never create:

- endless vertical card stacks
- centered everything
- giant empty hero spaces
- random grids
- unnecessary sections
- inconsistent alignment
- overcrowded dashboards
- repeated CTA buttons everywhere

# Failure Conditions

Layout fails when:

- User goal is unclear.
- Information hierarchy is missing.
- Components dictate structure.
- Mobile feels like compressed desktop.
- Scrolling becomes excessive.
- Everything becomes a card.
- Actions compete equally.

---

# Review Questions

Before approval:

- Can users immediately understand the page?
- Is the main action obvious?
- Does the layout guide the eye?
- Is information grouped correctly?
- Does mobile feel intentional?
- Is anything unnecessary?
- Does the layout feel calm?

---

# Final Rule

Great layouts disappear.

Users do not notice columns, grids, spacing, or alignment.

They simply feel that everything is exactly where it should be.

That is the goal of Layout Intelligence.
