# Visual QA System
**Version:** 1.0  
**Status:** Review Layer  
**Depends On:** Visual Language, Typography System, Color System, Spacing System, Elevation System, Component Intelligence

---

# Purpose

The Visual QA System is the final visual gate before any interface is approved.

No screen is considered complete because it "works."

It must also feel:

- premium
- intentional
- modern
- polished
- production-ready

This review exists to eliminate amateur UI before users ever see it.

---

# Core Philosophy

Users judge quality in under one second.

Visual polish is not decoration.

Visual polish is trust.

Every screen should feel like it belongs in a product built by companies such as:

- Linear
- Stripe
- Notion
- Airbnb
- Apple
- Arc
- Raycast
- Vercel

—not like a generated template.

---

# Review Pipeline

Every screen follows:

```
Layout Review

↓

Typography Review

↓

Spacing Review

↓

Color Review

↓

Component Review

↓

Visual Harmony

↓

Premium Polish

↓

Approval
```

---

# 1. Layout Review

Verify:

- logical structure
- balanced composition
- clear hierarchy
- intentional alignment

Reject if:

- sections feel random
- layout resembles stacked HTML
- cards appear pasted together

---

# 2. Typography Review

Verify:

- correct hierarchy
- readable scale
- proper weights
- consistent sizing

Reject if:

- every heading is bold
- body text is tiny
- font choices clash
- typography feels generic

---

# 3. Spacing Review

Every distance should follow the spacing system.

Check:

- internal padding
- section spacing
- alignment rhythm

Reject if:

- inconsistent padding
- crowded layouts
- random whitespace
- uneven margins

---

# 4. Color Review

Verify:

- semantic color usage
- restrained palette
- accessible contrast

Reject if:

- random accent colors
- unnecessary gradients
- oversaturated UI
- inconsistent button colors

---

# 5. Elevation Review

Inspect:

- shadows
- borders
- layering
- depth

Reject if:

- every card floats
- shadows dominate
- visual hierarchy is unclear

---

# 6. Component Consistency

Verify:

- identical buttons behave identically
- cards share one style
- forms are consistent
- icons use one family

Reject if:

- duplicate component styles exist
- visual language changes between screens

---

# 7. Icon Review

Check:

- one icon library
- consistent sizes
- correct alignment
- semantic meaning

Reject if:

- mixed icon styles
- decorative icons
- stretched icons

---

# 8. Visual Rhythm

Every page should have rhythm.

Users should naturally scan:

```
Hero

↓

Primary Content

↓

Supporting Content

↓

Actions

↓

Footer
```

Reject chaotic layouts.

---

# 9. White Space

White space should create hierarchy.

Reject:

- crowded screens
- giant empty gaps
- inconsistent breathing room

---

# 10. Mobile Review

View the screen only as a mobile user.

Ask:

- Can everything be reached comfortably?
- Is hierarchy obvious?
- Does it resemble a real mobile product?

Reject if it looks like:

Desktop HTML squeezed onto a phone.

---

# 11. Brand Consistency

Every screen should reinforce the same personality.

Ask:

Would someone recognize this as belonging to the same product?

---

# 12. Delight Review

Small moments matter.

Look for:

- polished hover states
- subtle motion
- refined loading
- elegant transitions

Reject gimmicks.

---

# Premium Product Test

Ask:

Would this interface look out of place inside:

- Apple
- Linear
- Notion
- Airbnb
- Arc
- Stripe

If yes:

continue improving.

---

# Screenshot Test

Take a screenshot.

Without interacting:

Can users identify:

- purpose
- primary action
- hierarchy

within three seconds?

If not:

redesign.

---

# Squint Test

Squint your eyes.

Can you still distinguish:

- hierarchy
- sections
- focal point

If everything blends together:

improve contrast and spacing.

---

# Distance Test

Zoom out to 25%.

Can the page still communicate structure?

Professional interfaces remain organized even at a distance.

---

# Visual Debt

Identify:

- duplicated styles
- inconsistent spacing
- legacy components
- mismatched patterns

Every release should reduce visual debt.

---

# Automatic Rejection Rules

Reject immediately if:

- more than two button styles exist
- spacing is inconsistent
- typography lacks hierarchy
- shadows are excessive
- cards are nested repeatedly
- icons come from multiple libraries
- colors lack semantic meaning
- layout resembles a template
- components are misaligned
- mobile feels secondary
